i5h benchmark

Can a coding agent prove what a real web app's code does?

Each task is one property of an open-source Rust application whose authorization logic was ported to an i5h kernel and extracted to Lean 4. The agent gets the kernel, the extracted Lean and a spec, and has to prove the property. Click any task to see the upstream Rust, the port, how the two are checked against each other, the Lean, and the proofs the models wrote.

Method

Ports

The kernel follows upstream function by function and changes the code only where Aeneas requires it (strings become byte slices, iterator adapters become loops) or where the code is not logic (metrics and logs). Every such change is listed in the port's deviations file.

Equivalence

A differential test runs the upstream functions, taken unchanged from the pinned commit, and the kernel on the same random inputs, and requires the same result. A deliberately mutated kernel must fail it.

Grading

A proof is accepted when it builds, its theorem has exactly the task's statement, and it depends only on propext, Classical.choice and Quot.sound. The reference proofs are not published.

Runs

Agents run in a container without network access, with the i5h Lean library and the i5h skill, for at most 40 minutes. An agent that stops early with the proof unfinished is resumed once.
