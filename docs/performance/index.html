How fast is a verified web server?

The same REST APIs on the same PostgreSQL data, written in Rust on h5i-app (whose CPU decisions are proved in Lean 4) and in Go, TypeScript and Python. Every implementation passes the same conformance suite, then runs under k6 at 1 to 256 concurrent clients.

Optional GPU search

Linkding HTTP API remeasurement · 2026-10-17. GPU acceleration is optional and especially useful for repeated, parallel text searches over a resident index.

These requests include authentication, database operations, search, pagination, tag fetching and JSON responses. At 16 clients, GPU throughput is 6.94× the resident CPU scan for simple search and 12.51× for complex search. CPU and GPU use the same application source and result path.

Optional GPU policies

RealWorld (Conduit) HTTP API remeasurement · 2026-10-18. The existing seven scenarios compare the same application with CPU or optional GPU policy decisions.

CUDA executes eight small authorization and state decisions. HTTP handling, JWT, input validation, bcrypt, SQL transactions and JSON responses remain shared. The workload and seed are unchanged. Guest list, slug and login do not call these GPU decisions and serve as controls. The CPU kernel has Lean proofs; the GPU implementation is checked against its CPU oracle and the shared API tests.

This workload shows no consistent end-to-end GPU benefit. Mixed throughput is 1.02× CPU at one client and 0.98× at 16; at 16 clients, mixed p99 is 71.16 ms on GPU versus 68.70 ms on CPU. Favorite falls to 0.87× at one client.   • 100 users, 10,000 articles, 10,000 comments, 1,000 follows and 5,000 favorites. Each point uses a reseeded database, a fresh server, 10 s warmup and 30 s measurement. Startup is excluded. Request rate includes k6's graceful stop; latency figures average per-repetition percentiles.

Methodology and reproduction · Summary CSV · Per-point CSV summaries

Method

Every point reseeds the database, warms up for 10 s and measures for 30 s. The published numbers are means of 3 repetitions.

  • Each server and its PostgreSQL get their own CPUs. In the serial runs, the server has 4 cores and k6 runs on separate cores. Python, Node and Go run 4 workers. Rust runs 4 tokio threads.
  • Requests/s is k6's http_reqs rate over the whole window, including the graceful stop. Latencies are k6 percentiles. RSS is the peak resident memory of the server's whole process tree.
  • Login hashes with bcrypt at cost 12 in every implementation, so that scenario measures bcrypt more than the framework.
  • These are runs on one host. Per-point CSV summaries, aggregate summaries and the scripts are in performance/.
