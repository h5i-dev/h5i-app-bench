Can a web backend be proved correct and still be fast?

h5i-app is a Rust framework whose kernel, the code that makes the decisions, is extracted to Lean 4 and proved there. This site holds two benchmarks for it: how much real code it can verify, and what that costs at runtime.

Benchmark 1 · Lean 4

Verification

Security logic from six open-source Rust servers, ported to h5i-app and stated as Lean 4 theorems. How many are proved, how much upstream code they cover, how much proof it takes, and how fast the port is against the original.

Open the verification results → Benchmark 2 · HTTP

Web performance

Real REST APIs (RealWorld and linkding) written in Rust on h5i-app and in Go, TypeScript and Python, on the same PostgreSQL data. Every implementation passes the same conformance suite; k6 measures throughput, latency and memory.

Open the performance results →

What each one answers

  • Verification asks how much of a real server's security logic fits in a verified kernel. A theorem proves one property of a function, not all of its behavior. Parsing, the database and I/O around the kernel are trusted. Source: prove/.
  • Web performance asks whether a server built that way is slower than one written without proofs. The h5i-app servers run their kernels on every request. Source: performance/.
  • Both are runs on one host. The scripts, raw results and summaries are in the repository.
