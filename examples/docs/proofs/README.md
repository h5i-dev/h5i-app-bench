# Proofs for the docs example

Lean 4 proofs about the Rust kernel in `../kernel`, as translated by Charon and
Aeneas. `DocsKernel.lean` is generated by `scripts/extract.sh`; do not edit it.

| File | Contents |
|---|---|
| `Schema.lean` | Generated by `schema!` from the kernel's row declarations: each row's SQL encoding, table number, key length, and the lemmas that the extracted `to_row`/`from_row` compute and invert it. `cargo test` fails if it is stale. |
| `Columns.lean` | Encodings of the app's own column types (`Role`, `Status`), which `Schema.lean` uses. |
| `Spec.lean` | The spec to review: policy table, list semantics of writes, invariants, effect-based authorization, `view`. |
| `Lemmas.lean` | Read-side helpers (`role_of`, `can`, `find_document`, ...) equal their list versions, via `I5hLib` loop lemmas. |
| `Apply.lean` | `apply` computes the list semantics of a write set, via `I5hLib` loop lemmas. |
| `Transition.lean` | Specs for the small helpers of `transition`. |
| `Theorems.lean` | `allows_eq`, `transition_total`, `apply_eq`, `authorized`, `reply_confined`. |
| `Invariants.lean` | `inv_preserved`, `reachable_inv`. |
| `Noninterference.lean` | `noninterference`. |
| `Frame.lean` | `transition_frame`: the result on the rows `read_scope` names equals the whole-tenant result. |
| `Check.lean` | `check_inv_spec`: the extracted invariant checker returns true iff `Inv` holds. |
| `Storage.lean` | The rows each table stores (`enc`), and `sql_writes_stored`: the kernel's table writes store exactly the rows of `applyAll`. |
| `Load.lean` | The kernel's `decode` inverts the encoding, and the tenant's rows always hold a state satisfying `Inv` (`fresh`, `load_sound`, `store_sound`). |
| `Scoped.lean` | Scoped loads: `scoped_sound` (the decoded slice is `Frame.slice` of a snapshot the rows hold) and `scoped_command` (the server's scoped path keeps `DbInv`). |

## What is proven

For every actor, every snapshot and every command:

- `allows_eq`: the kernel's permission table is the spec's.
- `transition_total`: the kernel never fails (no panic, overflow or bad index).
- `apply_eq`: `apply` matches the list semantics the database must implement.
- `authorized`: every write of a successful command is allowed by the policy,
  judged against the state before the command (four-eyes rule and status
  workflow included). An emitted effect goes only to the destination its
  project registered, and only when a writer publishes an approved document.
- `reply_confined`: replies contain only documents the caller may read.
- `inv_preserved`, `reachable_inv`: every reachable state has an owner per
  project, valid references, unique keys, fresh ids, the four-eyes rule, and
  an approver on a document exactly when it is approved or published.
- `noninterference`: two states that look the same to a user give that user
  the same result, including error codes. The id counter is a declared leak.
- `transition_frame`: a command's result depends only on the counter and one
  project's rows, so the server loads just those.
- `check_inv_spec`: the kernel's `check_inv` returns true exactly when `Inv`
  holds. Migrations use it to refuse changes that break an invariant.
- `sql_writes_stored`: the server stores a write set by running
  `i5h_sql::plan` on the kernel's `sql_writes`. If the tenant's rows hold a
  state satisfying `Inv`, the planned statements leave exactly the rows of
  `applyAll s ws`, under the PostgreSQL meaning of upsert and delete
  (`I5hLib.Sql.exec`). `encode_applyAll` is the invariant-free core: table
  writes commute with the row encoding. Key columns are encoded injectively
  (`int_u64`: a `u64` keeps its 64 bits in a `BIGINT`).
- `fresh`, `load_sound`, `store_sound`: the database invariant `DbInv` (the
  tenant's rows hold some state satisfying `Inv`) holds for an empty tenant;
  loading rows in any order decodes, with the kernel's `decode`, to a
  snapshot that satisfies `Inv` and that the rows hold; storing the writes of
  any successful command on it keeps `DbInv`. So the invariants are facts
  about the database, not only about kernel states.
- `scoped_sound`, `scoped_command`: the server's scoped path (counter, the
  named document's rows, then the four `WHERE ... = p` queries of the project
  the kernel's `scoped_project` picks) decodes to `Frame.slice snap sc` for a
  snapshot `snap` the rows hold. With `transition_frame`, the command's writes
  are the ones it would make on the whole tenant, so storing them keeps
  `DbInv`. Assumes each table has at most `usize::MAX` rows (`Fits`).

Every theorem depends only on `propext`, `Classical.choice` and `Quot.sound`.

## Shared library

Generic lemmas live in `crates/i5h/proofs` (`I5hLib`), required by relative
path: `loop_search` and `loop_fold` turn a per-step fact about an extracted
loop body into a spec for the whole loop, `I5hLib.upsert` defines table
writes, and `walk` / `i5h_step` execute extracted code symbolically.

## Size (2026-09-25)

Rust kernel: 801 code lines, including `read_scope` and the invariant checker.
Hand-written Lean for this app: 1576 lines, of which the spec is 139 and
proofs are 1437 (about 1.8 proof lines per kernel line). The shared library
`I5hLib` is 352 lines and is not specific to this app.

Per feature, after the library existed:

| Feature | Kernel lines | Spec lines | Proof lines |
|---|---|---|---|
| Webhooks and effects | 82 | 17 | 101 |
| Partial snapshots (`read_scope`, `Frame.lean`) | 32 | 0 | 160 |
| Invariant checker (`check_inv`, `Check.lean`) | 167 | 0 | 292 |
| Row encoding (`sql_writes`, `Storage.lean`) | 58 | 40 | 239 |
| Row decoding (`decode`, `Load.lean`) | 61 | 26 | 411 |
| Scoped loads (`scoped_project`, `Scoped.lean`) | 17 | 20 | 211 |

`Schema.lean` (155 lines, generated) replaced about 170 hand-written lines
in `Storage.lean` and `Load.lean`; the app writes 31 lines of `Columns.lean`
for its two enums.

The mutation suite catches 22 of 22 injected bugs.
